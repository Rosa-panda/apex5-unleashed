# ADR-014 游戏适配体系：四层信息源 + 游戏档案 + 前台自动切换

日期：2026-09-18

## 背景
用户要求游戏适配在 UI 上可见，并参考 DualSenseX 的社区模式（per-game JSON 档案 + 前台进程自动套用 + mod 生态）。
DSX 的"200+ 游戏"= 社区维护 JSON 档案仓库 + UDP mod ingress，非官方式逐游戏硬编码。

## 决定
1. **四层信息源并存**（不押注单一路线）：
   - ① DS 桥接（v0.2 主力，事件级）
   - ② 官方 93 包导入器（v0.2，一次性拉取转预设，不做运行时 API 依赖）
   - ③ DSX UDP 7878 ingress（v0.2，白嫖 mod 生态）
   - ④ 游戏档案 + 预设（本次落地，兜底 + 长尾）
2. **游戏档案格式**：`{name, exe: [小写进程名], preset_id, note, builtin}`，用户档案存 %APPDATA%\Apex5Unleashed\games\，
   内置档案随软件分发（已知热门游戏 7 条起步）。档案即 JSON 文件 → 未来社区仓库 PR 即贡献（DSX 打法）。
3. **前台检测 v0.1 用 1Hz GetForegroundWindow 轮询**（ADR-008 的 fallback 先行，SetWinEventHook 事件驱动 v0.2 升级），
   进程名匹配档案 → 自动应用其预设；切换有迟滞（仅前台 exe 变化时动作）；可通过 autoswitch 开关关闭。
4. 官方包导入的产物直接落同一档案格式——四层殊途同归于预设/档案两个原语。

## 后果
- "游戏适配"在 UI 可见：游戏库页卡片、前台游戏高亮、一键套用、自动切换。
- 档案是纯 JSON：社区贡献路径与 DSX 一致（提 PR 加文件）。
- 前台轮询 1Hz 成本可忽略（一个 Win32 调用），v0.2 换事件驱动无需改 UI。
