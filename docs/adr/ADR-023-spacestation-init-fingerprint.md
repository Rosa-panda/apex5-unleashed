# ADR-023 飞智空间站 init 指纹：接管横幅柔化（真接管、真放手）

日期：2026-09-20　状态：已采纳

## 背景

用户报告「经常说被代理，但没开任何代理软件；启动后一段时间才有，后面就没有了」。
真机抓取（2026-09-20 18:07，用户配合复现手柄开机）拿到完整时间线与帧原文：

```
t+0.0s  手柄上线，代理权=self
t+0.7s  proxy→external：cmd 4、cmd 7（服务握手）
t+2.2s  +cmd 161(0xA1)、cmd 2、cmd 16(0x10)；归因到「飞智空间站」
t+2.9s  +cmd 163(0xA3 设置块 168 包)、cmd 167(0xA7 灯表 76 包)
t+4.3s  +cmd 162(0xA2)、cmd 82(0x52 SyncWithGrip ×4)（真改了扳机绑定）
t+8.5s  +cmd 17(0x11 开体感流)——init 完成，服务收手
t+23s   15s 空闲超时 → 自动收回（账本重放），proxy=self
```

结论：**不是误报**。飞智空间站的 Windows 服务（Flydigi Space Station Service，
Manual 自启、设备接入触发）监听设备上线并做一轮初始化突发，其中 cmd 82 真的
写入了它自己的扳机路由参数；随后它自己停手，我们的 15s 空闲收回（ADR-013）
自动闭合。ADR-006 的「总线铁证」判定全程工作正确。

问题纯粹是 UX：这是日常操作（每次开手柄）触发的「被接管」橙色横幅，吓人且无行动价值。

## 选项

- A 保持现状：横幅如实显示接管+归因，15s 自动收回。行为正确但每天吓 N 次。
- B 指纹柔化（采纳）：识别空间站 init 指纹 → 同样记 external（收回/重放语义不变），
  但横幅降级为中性提示「飞智空间站服务初始化手柄，稍后自动收回」。
- C 按进程名白名单直接忽略：被否——进程在场≠在写总线（ADR-013 原则），
  空间站界面里用户真配扳机时也是同进程，不该一刀切。
- D 完全忽略这组命令：被否——cmd 82 是真写入，必须保留收回+账本重放。

## 决定

选项 B。指纹判定与代理权状态解耦：

- 指纹：10s 滑动窗口内命中 ≥3 种标记 cmd（{2,4,7,16,17,82,161,162,163,167}，
  来自上述实机抓取）→ 判 `mild`。
- `mild` 时代理权**仍置 external**（`proxy.mild=true`），收回超时、账本重放、
  手动夺回全部照旧——柔化的只是横幅措辞与颜色，不是检测语义。
- 窗口内 `mild` 状态变化只刷新状态不重复发事件（防刷屏，沿用 EXTERNAL_COOLDOWN 思路）。
- 未知进程若不命中指纹（真陌生接管），照旧红色横幅+「立即夺回」。

## 后果

- 开手柄的例行 init：一行中性提示，不再橙色警告。
- 帧原文（`ext_frames`）与 `proxy_hits.log` 落盘保留——指纹将来失配
  （固件更新改 init 序列）时能立刻发现并更新标记集。
- 理论残留风险：恶意/第三方进程若刻意模仿该指纹可伪装成 mild——
  接受：能模仿飞智私有 init 序列的对手，本工具的威胁模型里不设防。
