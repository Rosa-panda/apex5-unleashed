# ADR-013 代理权恢复策略：空闲超时 + 手动夺回 + 账本重放

日期：2026-09-18

## 背景
v0.1 首版把「代理进程在场」误判为接管（用户未开空间站主程序，仅服务自启即误报）；
且 external 一旦置位只有"归因进程退出"一条恢复路径，detail=未知进程时永远卡死。
用户明确要求：外部软件停手/退出后，必须**自动接管回来**，且要拿回实际控制权而非只翻标签。

## 决定
1. **判定与归因分离**：接管唯一铁证=总线外部命令 ACK（_external_hit）；进程扫描只做归因命名与弱提示（后台服务在场→info 事件）。
2. **恢复三通道**：
   - 自动·空闲超时：总线 15s（PROXY_RELEASE_TIMEOUT）无外部命令 → 自动恢复 self。持续接管者（震动流/配置流）会不断命中，不会误恢复；误恢复代价低（reassert 后若对方仍在写会立刻再次置位）。
   - 自动·归因加速：进程扫描发现归因进程消失可提前翻回（未实现为硬条件，超时兜底足够，保持单一恢复逻辑简单）。
   - 手动·夺回按钮：顶栏"立即夺回" → POST /api/proxy/reclaim，立即生效。
3. **控制权实夺 = reassert()**：恢复 self 时把锁存账本（LT/RT 模式参数、握把绑定、非零震动）原样重发。
   账本即"我们想要的"，接管期间被对方覆盖的效果一键夺回。panic 清账本，reassert 保账本，二者互补。

## 后果
- 误报类 bug（进程在场=接管）结构性消除：判定只剩总线证据。
- "卡死橙色"消除：任何 external 状态最多持续 15s+2s 扫描周期。
- reassert 是锁存账本模型的自然延伸；未来 DSX UDP ingress 的恢复同样复用该原语。
