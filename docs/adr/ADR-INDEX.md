# ADR · 架构决策记录索引（存量补录 2026-09-18）

> 格式：背景/选项/决定/后果。新决策追加编号，勿改旧条。

## ADR-001 游戏场景音频方案砍掉
背景：v1 全局跟随傻震，v2 事件驱动仍有 BGM 误触发。用户拍板"放弃！任何游戏都会有背景音乐"。
决定：游戏不走音频分析（信息论之墙：混音后事件意图不可恢复）。音频中间件仅历史保留，不入产品。
后果：产品=桥接(游戏)+预设(长尾)。

## ADR-002 K6/cmd87 实时流判死（八5）
背景：cmd 87 在八5 干净基线下 ACK-but-ignore；官方 SDK 逆向确认八5 适配 0 使用 K6 家族。
决定：不再扫 83-87 组合，不追八6 X-Haptics。
后果：八5 实时数据通道只有 cmd 18 流式 + cmd 82 路由。

## ADR-003 产品定位：桥接+实验室，不做官方平替
背景：官方 93 款适配=静态参数包+震动转发（逆向实锤），无事件级控制。
决定：只做官方架构做不了的（虚拟 DS 桥接、协议全开放、社区预设），键位/宏/陀螺转摇杆不重做。
后果：核心卖点依赖桥接质量 → 实测 B3/B4 为前置验证。

## ADR-004 UI：React+Vite+TS+Tailwind+深色科技风
背景：三案对比（React+shadcn / Vue+Naive / Svelte）。
决定：React 生态最大；shadcn 以 Tailwind token 手工实现（免 CLI 依赖）；bg #0a0a0f/强调 #22d3ee。
后果：壳 pywebview(WebView2)，前后端分离，未来可换壳。

## ADR-005 架构：Python 单服务 + webview 壳
背景：协议/验证资产全在 Python；C# 重写成本 2-3 天但音频已砍无 numpy 负担。
决定：v0.1 Python（FastAPI 127.0.0.1:18765 + WS），主线程 webview、uvicorn daemon 线程。C# 为长期备选。
后果：PyInstaller 体积 ~100MB 可接受；换壳不动核心。

## ADR-006 代理权检测=功能非风险
背景：用户指出官方也显示"被 Steam 接管"，且不止 Steam。
决定：三层检测（总线回显铁证/进程归因/一致性校验-v0.1不做），状态签不打扰。
后果：R11 降级；事件日志成为产品功能。

## ADR-007 许可证 GPLv3
背景：MIT 防不住闭源白嫖；CC BY-NC 非 OSI。
决定：GPLv3。商用允许但必须开源回馈。
后果：建仓时落实 LICENSE 与头部声明。

## ADR-008 游戏检测：SetWinEventHook（v0.2）
背景：官方 tasklist 轮询 → 云端意见建议事件驱动。
决定：EVENT_SYSTEM_FOREGROUND 钩子（需独立消息泵线程），失败退 1Hz GetForegroundWindow 轮询。
后果：切换零延迟；实现糙点已知。

## ADR-009 DSX UDP ingress（v0.2）防洪坝位置
背景：接 7878 兼容 DSX mod 生态。云端意见建议收包端丢旧留新。
修正决定：收包端只排空（内核自然丢包），按指令类型分流——状态类 latest-wins 单槽、瞬态类必达小队列；限频坝建在 HID 写出层（真瓶颈是 32B 中断端点）。
后果：不丢瞬态事件（脉冲类）；端口冲突探测入 R13。

## ADR-010 启动卫生检查
背景：atexit/SIGINT 拦不住 TerminateProcess；发生过强杀残留效果事故。
决定：每次设备连上先无条件 panic（反正账本为空，清的是历史残留）。
后果：强杀场景自愈；SIGINT 仍注册（免费）。

## ADR-011 Mock 设备层
背景：R4 硬件在环单点。
决定：Transport 抽象 HidPad/MockPad（5ms 合法 ACK），无手柄自动 Mock；未来 trace 回放挂同层。
后果：全自动开发/CI 成为可能。

## ADR-012 HID 单读写线程 + 10ms 超时读
背景：审阅指出 hid_read 阻塞饿死写。
决定：线程H主循环 读(10ms超时)→写队列→发；真防线是"单处 open 设备"（hidapi 写读本可跨线程）。
后果：流式命令与队列命令共用写锁防帧交错。

## ADR-013 代理权恢复策略：空闲超时 + 手动夺回 + 账本重放
背景：检测到被接管后怎么回来、回来后效果状态怎么保证。
决定：外部命令空闲 15s 自动夺回 + UI 手动夺回；reassert 把账本原样重发（夺回的是实际控制权）。
后果：锁存账本模型闭环；进程扫描只做归因命名，接管判定只信总线铁证。

## ADR-014 游戏适配体系：四层信息源 + 游戏档案 + 前台自动切换
背景：参考 DualSenseX 的社区模式（per-game JSON 档案 + 前台进程自动套用）。
决定：档案=纯 JSON（官方包/DSX 档案/内置/用户自建归一），SetWinEventHook 前台切换，进游戏自动套预设。
后果：社区贡献路径=提 PR 加文件；实现见 gameprofiles.py。

## ADR-015 统一游戏配置格式 apex5-game-config/1
背景：官方 protobuf 包 / DSX JSON / 自有预设三方格式割裂，用户要"让别人自己开发配置"。
决定：startup（进场静态）+ events[]（事件规则，字段引用 $xxx）统一格式；导入器吃两家。
后果：格式先行；事件段依赖 ingress 到位激活（UDP ingress 随 ADR-020 后待定）。

## ADR-016 拓展键方案：0xA3 映射写入是 6 键可见的唯一通路
背景：六拓展键（M1-M6/背键头键）在协议里的可见性与改键方式。
决定：键表（blob 13+id*3）target 写入实现映射；0xEF 位图为唯一实时检测源。
后果：拓展键映射/测试模式/宏触发键共用此通路（详见 ADR-019/021）。

## ADR-017 官方逐游戏适配导入 + 通用震动联动 + 自定义 exe
背景：官方空间站有 93 款 adapterTriggerGames.json，白嫖其数据。
决定：一键导入官方包（vib 字段→通用震动联动）；特殊版本游戏支持手动定位 exe。
后果：内置热门档案随软件分发；mod_only 条目只做震动兜底。

## ADR-018 RGB 灯光配置 + 屏幕 GIF 自定义动画
背景：灯表（0xA7 多包读/写）与屏幕动画（GIF 转帧烧写）均无官方开放入口。
决定：灯光五模式（on/off/breath/gradient/flow）配置读写+备份还原；屏幕帧烧写红线=必须 confirm=true 且用户知情。
后果：实现见 engine.led_* / screen_*；备份含整机配置槽。

## ADR-019 拓展键映射写通路 + 测试模式（宏前置）
背景：六键改键需可靠写通路与真机验证，作为板载宏的前置。
决定：独占 Pad 会话（161-166 命令族，与引擎读线程并存，Windows 多句柄复制输入）+ 测试模式一键映射 Gamepad 可见目标。
后果：宏的写路径直接复用；「私有原始数据」开关（cmd17）RAM 态丢失问题在此期发现。

## ADR-020 DS 桥接「指挥官」模式 → 封存 → **彻底删除**
背景：v0.2 主力的虚拟 DualSense 桥接（ASB+usbip+HidHide）经真机实测：链路健康（p50=68µs）但 PC 上 DS 输入依赖 Steam Input 翻译层，消费端结构性缺失；卸载驱动又引发 USB 栈事故。
决定：revA 封存 UI → revB 全量删除（asb.py/engine 仲裁/API/前端页面/测试，代码零残留），仲裁回归 self/external 两态。
后果：与驱动层路线彻底切割，「零外部依赖」兑现；实测方法论 B1-B5 存档于 TEST-PLAN（废弃标注）。

## ADR-021 板载宏（v3.1 方案）
背景：固件宏执行、关软件照样触发。首版 172 独立宏区方案在 k5 上被真机证伪（总回 1/4 包，属 v3.2 设备路径）。
决定：宏页在 163 配置 blob 偏移 230（协议 v3.1，openflydigi 实证）：≤5 条/单条 ≤64 步/全页 128 步/10ms tick；42 包一次读写提交（连触发键绑定），162 应用+166 保存；宏无名字，身份=触发键。
后果：写入路径复用 ADR-019 的 Pad 会话；162/166 不清「私有原始数据」开关，attach/写后均补 cmd17。
