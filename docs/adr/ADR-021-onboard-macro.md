# ADR-021：板载宏功能（任务 #8 收官）

日期：2026-09-19（协议逆向完成；实现当日落地，真机验证项见文末）

> ## ⚠️ 修订（2026-09-19 晚，真机打脸 V10 假设——以本节为准）
>
> **k5（Apex5, proto v3.1）的宏不在 172 独立配置区里，而在 163 profile blob 偏移 230 的宏页内。
> 172/173/174 是 v3.2 机型（Vader 5 等）的通路；k5 固件的 172 实测恒回 total=4 但只发包 0，
> 游标不推进——不可用。** 依据：openflydigi（工作区 `flydigi-apex5-re\openflydigi`，真机
> Apex 5 硬件验证的开源实现）+ 本机只读探针逐字节复核（proto=3.1、宏页 count=0、间隔字节
> 出厂 `[3,3,3,3,3]`=30ms，与 openflydigi 文档吻合）。
>
> v3.1 宏页布局（blob 内，openflydigi 实锤）：
> - `blob[230:768]` 宏页 538B：`[0]`=宏数 1..5（其余值=无宏）；`[1..6]`=每槽偏移（单位 4B，
>   相对页内 6）；每条宏 = 4B 头（触发键 id，步数 u16 LE，类型 1=单次/2=按住循环/3=点击循环）
>   + N×4B 步骤（累计时间 u16 LE **单位 10ms tick**，键 id，事件 0=抬起 1=按下 5=按住）；页尾 FF 填充
> - `blob[820:825]` 每槽循环间隔字节（×10ms，0xFF=未设，上限 2540ms，出厂 30ms）
> - 触发键绑定 = 键表 target=32（与原结论一致）；**宏页必须 162 应用后才被固件解析播放**（openflydigi 实测）
> - 限制：≤5 条宏，全页合计 ≤128 步（单条 ≤64，固件 step[64]）；v3.1 页**没有宏名字段**（前端以触发键为身份）
>
> 写通路改为复用键表已验证的 163 读 → 改 blob（宏页+间隔+键表绑定一次改）→ 164/165 写 →
> 读回 → 162 → 166。**2026-09-19 真机已验证：写入 M1→A(100ms) 单次宏成功（version 55685），
> 读回逐字节一致，M1 键表 target=32。** 下方 V10 章节 72/173/174/1620B 部分仅对 v3.2 机型成立，留档。



## 背景

ADR-019 打通拓展键写通路并发现 0xEF 帧全键物理位图后，宏是最后一环。用户确认走
「板载宏为主、软件宏后补」的分层路线（2026-09-19 会话拍板）。

## 逆向结论（spacestation decomp，MacroConfigParser V10 + 命令族，全部一手实锤）

### 命令族（与键表 161-166 / 灯光 167-169 同构，CRC=累加和封装）
| cmd | 作用 | 帧 |
|---|---|---|
| 172 | 读宏配置 | build_crc(172, [cfgId, pkgSize=20])；多包 ACK：body[3]=总包数 body[4]=序号 数据@body[6:26]；**固定 81 包×20B=1620B** |
| 173 | 写-开始 | build_crc(173, [cfgId, startIndex, packetNum, 20]) |
| 174 | 写-数据包 | build_crc(174, [packNum] + 20B) |
| 162/166 | 应用/保存 | 与键表共用（按 cfgId / version u16） |
| 80 子6 | 硬件宏总开关 | C# 索引有歧义（CreateSimpleCommand(false) + array[2]=6, array[3]=0开/1关），**真机验证后再接入** |

### 宏 blob（V10 解析器，1620B，0xFF 填充）
```
[0:2]   version u16 LE
[2:4]   宏数量 u16 LE（1~10）
[4:24]  10 × u16 LE 偏移表（单位 4B，相对数据区起点 24；空槽 FFFF）
@24     每条宏：32B 头 + N×4B 动作
  +0      KeyId 触发键（ControllerKey 枚举，18-23=六拓展键）
  +1:3    动作数 u16 LE（≤64，m_fdg_macro_unit_struct_t SizeConst）
  +3      Type：1=Once 触发一次 2=Press 按住循环 3=Click 按下循环再按停
  +4:6    循环间隔 u16 LE (ms)
  +6:12   6B 0xFF 保留
  +12:32  20B UTF-8 配置名（0xFF 填充）
  +32起   动作 [累计时间 u16 LE (ms), 键 id, 事件]；事件 0=抬起 1=按下 5=保持
偏移单位验证：offset[j] 累计 = Σ(count+8)（32B 头 + count×4B 换算成 4B 单位 = count+8）
```
官方校验（UI 文案实锤）：按下/抬起必须配对；总时长 ≤65s（u16 ms 天然上限 65535）；
动作数上限；容量 1620B（数据区 1596B → 10 宏平均 ≤31 步）。

### 绑定语义
键表（163/164 区）条目 target=32（ControllerKey_Macro）→ 该键进宏模式；
宏记录头 KeyId 决定绑定哪条宏。硬件执行，软件退出后宏仍在（板载）。

## 决策

1. **路线 A 板载宏先行**：录制（0xEF 位图事件）→ 编辑（时间轴 UI）→ 173/174 写入 +
   键表 target=32 绑定 + 162/166。执行在固件，零延迟、游戏零兼容负担。
2. **软件宏后补**（本 ADR 不实现）：键鼠 SendInput 序列、摇杆轨迹等板载做不到的能力。
3. 触发键 v1 限六拓展键（M1-M6/LM/RM）——产品定位就是给拓展键赋能；普通键改宏
   伤游戏可用性，不做 UI 入口（协议层不设限）。
4. 录制源 = engine 新增全键位图变化事件（0xEF body[11..14]，ADR-019 修订 B 已解码，
   现只发拓展键事件，本次扩展为全键）。**录制的是物理键**（映射前），与宏动作键 id 同源。
5. 写前备份宏区原 blob（%APPDATA%\Apex5Unleashed\macro_backup.bin）+ 恢复端点。
6. UI 入口：主导航「宏」页（列表 + 时间轴编辑器 + 录制）；手柄测试页 M 键区加
   「设为宏触发」快捷跳转（后续打磨项）。

## 风险 / 真机验证清单

1. 172 读出厂宏区（预期 0xFF 或空配置）→ 解码验证 81 包布局。
2. 最小宏（M1→A×3，Once）写入 + 键表绑定 + 按压实测。
3. cmd80/子6 总开关帧格式（decomp 索引歧义，必要时 USBPcap 抓官方写帧定格式）。
4. 事件 5=Hold 与摇杆事件 2/3 在 k5 上的行为（官方 UI 有摇杆宏，k5 支持度未知）。
5. cfgId 语义：宏区是否随键表槽位切换（v1 用 active 槽，实测确认）。
