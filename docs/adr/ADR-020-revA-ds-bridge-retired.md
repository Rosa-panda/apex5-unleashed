# ADR-020 修订 A：DS 桥接功能封存（2026-09-19）

## 状态

已接受 —— DS 桥接从产品功能面移除（UI 入口下线），后端指挥官代码休眠保留。

## 背景

ADR-020 原始决策「指挥官模式」已于 2026-09-19 完成全量实现并实测（任务 #2/#7/#11）。
实测结论推翻了前提假设：

1. **链路本身健康**：物理盘→ASB 读取（~800Hz）→ 虚拟 DualSense 全量代理（p50=68µs）
   全部探针实证可用；自动识别（learning + database）正常。
2. **游戏消费端结构性缺失**：PC 上 DualSense 输入实际依赖 Steam Input 翻译层（或极少数
   原生 DS 支持的游戏）。本机游戏库（学习版/无 Steam）两头不沾——生化9 为上游识别 bug
   （正版同病，Steam 社区实锤），碧蓝 Relink 学习版整个会话 dualsense_output_reports=0
   （从不绑定 DS）。
3. **ASB 隔离机制伤及无辜**：HidHide 隔离会连物理盘的 XInput（XUSB）一并摘除，且会话
   间歇期存在粘性不恢复问题（XInputGetState 探针抓到 pad0 err=1167）——桥接活动会直接
   破坏非桥接游戏的正常输入，与本产品「零负担共存」的定位冲突。

## 决策

1. **移除产品 UI 中的「DS 桥接」入口**（前端导航/页面下线），用户不可见。
2. 后端 asb.py / engine bridge 仲裁 / 相关 API 休眠保留（不删代码，无害；若未来目标用户
   群变成正版 Steam 玩家，可低成本复活）。
3. 游戏档案 ds_bridge/prompts 字段保留但不再有 UI 入口。
4. 本机卸载 ApexSenseBridge 及其自有驱动（usbip-win2 / HidHide），清理自启项。
5. 主路径不变：扳机模式 + cmd 0x52 通用震动联动 + 官方逐游戏适配 + 灯光/屏幕/拓展键。

## 后果

- 产品更轻：无外部依赖、无驱动、无共存风险；「零负担」承诺恢复完整。
- 失去（从未真正拥有的）：PS 移植游戏的事件级自适应扳机效果——该能力对无 Steam 环境
  本就不可达。
- 开发资产保留：B1-B5 全套探针方法论与机理结论记录于 APEX5-DEV-STATUS.md，可复用。
