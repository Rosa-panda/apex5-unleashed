# ADR-031: 拓展键一等公民——默认透传 + UI 实时显示自动跟页

日期: 2026-09-22
状态: 已采纳（修正 ADR-030 的默认值语义）
背景: ADR-030 落地后用户实测「拓展键不能用」。排查发现信号链路全通，真正的问题
出在产品语义，且与用户需求错位：

1. **默认映射语义错误**：ADR-030 默认把六键映射到手柄已有键位（select/start/
   LB/RB/C/Z）。用户视角这毫无意义——按 M3 手柄图上亮的是 LB，M 键被「藏」进
   了已有键里。出厂真值是全 255 透传（FACTORY_K5 实测）：官方默认拓展键不别名
   任何键，是独立按键。
2. **UI 显示被手动开关闸死**：手柄图上 M1-M4/LM/RM 六颗键早画好了（PadDiagram
   extNow），点亮数据源也有（0xEF 位图→engine extkey 事件），但被「拓展键监听」
   手动开关（默认关）闸住。用户按 M 键 UI 永远不亮，「不能用」的体感即来自此。

决策:
- **拓展键=一等键**：默认透传（255，出厂态）。按 M 键只代表 M 键本身，经 0xEF
  流在 UI 实时显示；不往标准手柄报文里注入任何已有键位。
- **UI 监听自动跟随页面可见性**：测试页可见即自动开 0xEF 流（15s 心跳保活），
  离开页面/切走标签页即自动收流——修复 ADR-028 修订 2 的体验缺陷（手动开关），
  同时保住其核心语义（流常开=手柄不休眠，只允许在「用户正看着」时开）。
  手动开关保留为强制关闭手段。
- **映射降级为可选增强**：gamepad/keyboard 模式仅在用户显式配置时生效（写固件
  键表 / SendInput 注入）。默认 passthrough 不写设备。
- **宏设计依赖此语义**：宏录制/回放把拓展键当独立触发源，别名化（ADR-030 默认）
  会让宏无法区分 M 键与被别名键——此为本 ADR 的前置理由。

影响:
- extkeymap.DEFAULTS 全改 passthrough；已写入真机的六键别名（v29654）清回 255。
- PadTest 拓展键监听改自动跟页（mount 开、unmount/document.hidden 收）。
- ADR-030 中「默认=老行为」的表述作废，以本 ADR 为准。
