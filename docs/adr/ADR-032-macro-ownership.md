# ADR-032: 宏功能完善——键表单一所有权 + 宏区作用域恢复 + 宏管理增强

日期: 2026-09-22
状态: 已采纳
背景: 用户确认宏主要绑在六拓展键上使用（固件 target=32 触发是拓展键与宏联动的
唯一通路），要求从用户视角完善宏功能。排查发现宏与拓展键映射存在键表双写者
冲突，且恢复/管理体验有硬伤。

决策:
1. **键表单一所有权（修 P1）**：六拓展键的键表 target 由**一条规则**统一裁决——
   **宏绑定(32) > 映射配置（gamepad 目标/透传 255）**。
   - `macro.write` 成为六键键表的唯一写入者：按上述规则一次写全六键，宏写入时
     把被占键的映射配置归位 passthrough（防配置与设备脱节）；删除宏后该键自动
     回落映射配置（通常=透传）。
   - `extkeys.set_targets` 写前读宏页，**跳过宏占用键**并在返回值里报 `skipped`
     （UI 显示「宏占用」）；映射卡不再可能踩掉宏。
   - 宏写入后 Router 同步 `ctx.extkeymap.reload()`（键盘注入边沿状态对齐）。
2. **恢复缩小到宏区作用域（修 P3）**：`macro/restore` 不再全量回写 840B 配置槽，
   只拼接宏页(230..768) + 循环间隔(820..825) + 六拓展键键表项，其余字节保留
   设备当前值；确认弹窗文案同步。
3. **宏管理增强**：
   - 宏列表加「复制」：以已有宏的动作序列新建宏（触发键自动让位到空闲键）。
   - 宏导出/导入（JSON 文件）：五槽 128 步的稀缺资源可存档/迁移配置槽/换机。
   - 导入走同一 validate 白名单，非法直接拒绝。
4. `unbind` 参数废弃（保留兼容但不再使用）：删除宏 = 宏列表少一条，键表由规则 1
   自动回落，前端不再传 unbind。

非目标: 不改宏页二进制布局（v3.1）、不突破固件上限（5 条/64 步/128 步/655s/
10ms）、不把拓展键加进宏动作（固件语义：拓展键是触发位不是动作位）、不做
PC 侧宏播放（板载宏离手可用的卖点不破坏）。
